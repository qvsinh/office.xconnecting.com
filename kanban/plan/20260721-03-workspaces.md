# 03 — Workspaces

**Goal:** Any signed-in user can create workspaces; members join; owner/admin
manage membership (incl. bulk-add a whole group). Ships tested.

**Depends on:** 01, 02.

## Files
- Create `app/Controllers/Workspaces.php` (client area, authFilter only).
- Views: `app/Views/workspaces/index.php` (card grid), `workspaces/show.php`
  (overview + members + projects list link), `workspaces/members.php` partial or
  section within show.
- Modify `app/Config/Routes.php` (authFilter group), `app/Views/layouts/app.php`
  (client nav: "Workspaces").
- Tests: `tests/feature/Web/WorkspacesTest.php`.

## Routes (inside the `authFilter` group)
```
$routes->get('workspaces', 'Workspaces::index');
$routes->post('workspaces/create', 'Workspaces::create', ['filter'=>'csrf']);
$routes->get('workspaces/(:num)', 'Workspaces::show/$1');
$routes->post('workspaces/update/(:num)', 'Workspaces::update/$1', ['filter'=>'csrf']);
$routes->post('workspaces/delete/(:num)', 'Workspaces::delete/$1', ['filter'=>'csrf']);
$routes->post('workspaces/(:num)/join', 'Workspaces::join/$1', ['filter'=>'csrf']);
$routes->post('workspaces/(:num)/leave', 'Workspaces::leave/$1', ['filter'=>'csrf']);
$routes->post('workspaces/(:num)/members/add', 'Workspaces::addMember/$1', ['filter'=>'csrf']);
$routes->post('workspaces/(:num)/members/remove', 'Workspaces::removeMember/$1', ['filter'=>'csrf']);
$routes->post('workspaces/(:num)/members/add-group', 'Workspaces::addGroup/$1', ['filter'=>'csrf']);
```

## Behaviour + access
- `index()` — `WorkspaceModel::forUser(current_user_id())` as a responsive card
  grid; "New workspace" opens a create modal. Also show discoverable
  `visibility='company'` workspaces the user hasn't joined, with a Join button.
- `create()` — creator becomes `owner` (insert workspace + workspace_member
  role=owner). Validate name required.
- `show($id)` — 403/redirect unless `workspace_role($id) !== null`. Shows
  description, member avatars/list, projects (link to feature 04), and a
  Settings/Members panel visible only when `can_manage_workspace($id)`.
- `update/delete` — require `can_manage_workspace`. Delete soft-deletes and
  cascades (soft) — keep simple: soft-delete workspace; projects/tasks under it
  remain but are unreachable (guard in feature 04 by checking workspace not
  deleted). `delete` only by `owner`.
- `join()` — only when `visibility='company'`; adds member role=member.
- `leave()` — removes self unless sole owner.
- `addMember/removeMember` — require `can_manage_workspace`; role in
  owner/admin/member/viewer. `addGroup` — bulk-insert every member of a group as
  role=member (dedup). Return JSON with the added count.

## UI notes (TailAdmin, mobile-first)
- Card grid: `grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-4`. Each card:
  name, member count, project count, role badge, "Open" link.
- `show` uses a header + tabs (Overview / Members) via Alpine, stacking on mobile.
- Members management uses the shared confirm/toast; add-member = user `<select>`
  + role `<select>`; add-group = group `<select>`.

## Tests
- create → creator is owner; forUser returns it. Non-member cannot `show`
  (redirect/403). company workspace join works; private cannot be joined.
  addMember/removeMember gated to managers. Sole owner cannot leave.
