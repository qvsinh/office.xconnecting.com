# 08 — Dashboards (company + personal)

**Goal:** A company-wide dashboard for admins and a personal dashboard for every
user, both attractive and mobile-friendly. Tested (data + gating).

**Depends on:** 01, 03, 04, 05.

## Files
- Modify `app/Controllers/Admin/Dashboard.php` (company stats).
- Modify `app/Controllers/Client/Dashboard.php` (personal stats).
- Rewrite `app/Views/admin/dashboard.php` and `app/Views/client/dashboard.php`.
- Optional: `app/Models` count helpers (add small count methods where missing;
  reuse existing where possible).
- Tests: extend/`tests/feature/Web/DashboardsTest.php`.

## Company dashboard (`/admin/dashboard`)
Stat cards: total users (active), total groups, workspaces, projects, open tasks,
tasks completed (in a "Done" column) — compute simply. Plus:
- "Tasks by priority" mini bar (counts).
- "Recent workspaces" and "Recent projects" lists (latest 5).
- "Most active projects" = projects with most open tasks (top 5).
Keep all counts as cheap `countAllResults()` / grouped queries in models — no N+1.

## Personal dashboard (`/dashboard`)
- Greeting + stat cards: my workspaces, my projects, my open tasks, tasks due soon.
- "My tasks" list: `TaskModel::forAssignee(current_user_id())` grouped by
  due/overdue, each linking to its project board. Priority pill.
- "My workspaces" quick cards (link to each).
- Empty states with a CTA ("Create your first workspace").

## UI (TailAdmin, mobile-first)
- Stat cards grid `grid-cols-2 lg:grid-cols-4 gap-4`, each: icon, label, big number.
- Lists as simple responsive tables/cards. No chart library — use CSS bars
  (ponytail: a div width % is enough for the priority breakdown).

## Tests
- Company dashboard renders for admin with correct counts after seeding a few
  workspaces/projects/tasks; blocked for client (adminFilter).
- Personal dashboard shows the user's assigned tasks and their workspaces only
  (no leakage of others' data).
