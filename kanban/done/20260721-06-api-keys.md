# 06 — Personal API Keys

**Goal:** Each user creates/manages personal API access keys (for AI agents).
The plaintext token is shown once at creation; only a hash is stored. Tested.

**Depends on:** 01 (ApiKeyModel).

## Files
- Create `app/Controllers/Account/ApiKeys.php`.
- View: `app/Views/account/api_keys.php`.
- Modify `Routes.php` (authFilter group, under `account`), `layouts/app.php`
  (Account nav: "API Keys").
- Tests: `tests/feature/Web/ApiKeysTest.php` (model resolve covered in 01).

## Routes
```
$routes->get('account/api-keys', 'Account\ApiKeys::index');
$routes->post('account/api-keys/create', 'Account\ApiKeys::create', ['filter'=>'csrf']);
$routes->post('account/api-keys/revoke', 'Account\ApiKeys::revoke', ['filter'=>'csrf']);
```

## Behaviour
- `index()` — list current user's keys (name, prefix, scopes, last_used_at,
  expires_at, revoked state, created_at). Never render the hash/plaintext.
- `create()` — validate name required max 100; scopes in {read, write} (default
  read); optional `expires_days` (int) → expires_at. Calls
  `ApiKeyModel::createForUser`, returns the **plaintext token once** in the JSON
  envelope (`token` field) plus the row. UI shows a copy-once panel and warns it
  won't be shown again.
- `revoke()` — set `revoked_at`; scoped to `current_user_id()` (a user can only
  revoke their own keys — 404 otherwise). IDOR guard.

## UI (TailAdmin, mobile-first)
- Table of keys with a status badge (Active/Revoked/Expired) + Revoke button
  (shared confirm). "Create key" modal (name, scope select, expiry select).
- After create: a highlighted one-time reveal box with the token + copy button
  (`window.copyText`) + a "Connect your agent" link to `/docs/api` (feature 09).

## Tests
- create returns a `sk_`-prefixed token once and stores only prefix+hash; list
  never exposes hash; revoke scoped to owner (another user's key → 404); expired
  key shows Expired badge.
